# 0001 — Kernel language: Rust

> 🇧🇷 [Ler em Português](../../pt-br/decisions/0001-rust.md)

**Status**: Decided (foundational, before M0). **Area**: whole project.

## Context

The kernel's implementation language is the single most expensive decision
in the project to reverse — it determines the toolchain, what kinds of bugs
are even possible to write, and the shape of all future code. This needed
to be settled before M0 (toolchain bring-up).

## Alternatives considered

- **C** — the historical default for OS development (Linux, xv6, seL4,
  most of the OSDev Wiki). Low language-learning curve, keeping the
  learning curve isolated to OS development itself. Rejected primarily
  because it offers no memory safety guarantees: a wild pointer in the
  kernel is a potential security failure, which directly conflicts with the
  project's stated first priority.
- **C++** — more abstraction over C, but manual memory management remains,
  and brings kernel-space complications (exceptions, RTTI, a less
  predictable ABI) with limited net benefit for this project.
- **Rust** — memory safety by construction (the borrow checker), no
  garbage collector, and a bare-metal OS-dev ecosystem that was already
  mature enough to rely on (real crates for CPU/register access, a
  maintained bootloader ecosystem, the "Writing an OS in Rust" reference
  material, and a real precedent in Redox, a complete Rust OS). The
  accepted cost: a steeper initial learning curve (fighting the borrow
  checker inside `unsafe`/`no_std` code while simultaneously learning OS
  development), and fewer copy-paste-ready tutorials than the C-dominated
  OSDev Wiki.

## Decision

**Rust**, for the kernel and, going forward, the runtime/SDK layers.
Assembly (NASM) is used only where genuinely unavoidable (the boot entry
stub, context switching, interrupt stubs). C is permitted only as a
pointed exception, if a low-level library with no Rust equivalent ever
needs vendoring — that exception hasn't been exercised so far.

## Consequences

- Memory-safety-related bug classes common in C kernels (buffer overflows,
  use-after-free, many data races) are eliminated by construction rather
  than by relying on sustained human discipline across years of
  development.
- The project accepted a real, upfront cost in development speed for the
  earliest milestones, in exchange for that guarantee holding for the rest
  of the project's lifetime.
- Rust's bare-metal ecosystem being production-adjacent (used in projects
  like AWS Firecracker, and in parts of Windows and Android) was treated as
  evidence the ecosystem risk was acceptable, not merely a hopeful bet.
