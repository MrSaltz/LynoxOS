# 0001 — Linguagem do kernel: Rust

> 🇺🇸 [Read in English](../../en/decisions/0001-rust.md)

**Status**: Decidido (fundacional, antes de M0). **Área**: projeto inteiro.

## Contexto

A linguagem de implementação do kernel é a decisão mais cara do projeto
inteiro de reverter — ela determina a toolchain, que tipos de bug são
sequer possíveis de escrever, e a forma de todo código futuro. Isso
precisava ser resolvido antes de M0 (bring-up de toolchain).

## Alternativas consideradas

- **C** — o padrão histórico pra desenvolvimento de OS (Linux, xv6, seL4,
  a maior parte da OSDev Wiki). Curva de aprendizado da linguagem baixa,
  mantendo a curva de aprendizado isolada ao desenvolvimento de OS em si.
  Rejeitada principalmente porque não oferece nenhuma garantia de
  segurança de memória: um ponteiro selvagem no kernel é uma falha de
  segurança em potencial, o que conflita diretamente com a prioridade #1
  declarada do projeto.
- **C++** — mais abstração sobre C, mas gerenciamento manual de memória
  continua, e traz complicações de espaço de kernel (exceções, RTTI, uma
  ABI menos previsível) com benefício líquido limitado pra esse projeto.
- **Rust** — segurança de memória por construção (o borrow checker), sem
  garbage collector, e um ecossistema de OS dev bare-metal que já estava
  maduro o suficiente pra confiar nele (crates reais pra acesso a
  CPU/registradores, um ecossistema de bootloader mantido, o material de
  referência "Writing an OS in Rust", e um precedente real em Redox, um
  SO completo em Rust). O custo aceito: uma curva de aprendizado inicial
  mais íngreme (lutar com o borrow checker dentro de código
  `unsafe`/`no_std` enquanto simultaneamente se aprende desenvolvimento de
  OS), e menos tutoriais prontos-pra-copiar-e-colar do que a OSDev Wiki
  dominada por C.

## Decisão

**Rust**, pro kernel e, daqui pra frente, pras camadas de runtime/SDK.
Assembly (NASM) é usado só onde genuinamente inevitável (o stub de
entrada do boot, troca de contexto, stubs de interrupção). C é permitido
só como exceção pontual, se algum dia for necessário vendorizar uma
biblioteca de baixo nível sem equivalente em Rust — essa exceção não foi
exercitada até agora.

## Consequências

- Classes de bug relacionadas a segurança de memória comuns em kernels C
  (buffer overflow, use-after-free, muitos data races) são eliminadas por
  construção em vez de depender de disciplina humana sustentada ao longo
  de anos de desenvolvimento.
- O projeto aceitou um custo real e antecipado em velocidade de
  desenvolvimento nos primeiros milestones, em troca dessa garantia se
  sustentar pelo resto da vida do projeto.
- O ecossistema bare-metal do Rust ser adjacente a produção (usado em
  projetos como AWS Firecracker, e em partes do Windows e Android) foi
  tratado como evidência de que o risco do ecossistema era aceitável, não
  meramente uma aposta esperançosa.
